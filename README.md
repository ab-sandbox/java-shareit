## ShareIt

REST API для сервиса совместного использования вещей. Пользователи могут размещать вещи, доступные для аренды,
бронировать вещи других пользователей и оставлять отзывы после завершения аренды.

### Технологии

- Java 21
- Spring Boot 3.3.2
- Spring Data JPA / Hibernate
- PostgreSQL 16
- H2 (интеграционные тесты)
- Maven
- JUnit 5, Mockito
- Docker Compose
- Postman / Newman

### Функциональность

- Создание, просмотр, обновление и удаление пользователей.
- Добавление, редактирование и поиск доступных вещей.
- Создание бронирований и подтверждение или отклонение заявок владельцем вещи.
- Просмотр бронирований с фильтрацией по статусу.
- Отображение предыдущего и следующего бронирования для владельца вещи.
- Добавление отзывов после завершенного подтвержденного бронирования.
- Просмотр отзывов о вещах.

### Запуск

Для запуска необходимы JDK 21, Maven и Docker с поддержкой Docker Compose.

**1. Запустить PostgreSQL**

```bash
docker compose up -d
```

**2. Запустить приложение**

```bash
mvn spring-boot:run
```

После запуска API доступен по адресу:

`http://localhost:8080`

Для остановки контейнеров:

```bash
docker compose down
```

### Тестирование

#### Автоматические тесты

В проекте используются модульные тесты сервисов с Mockito, тесты контроллеров с MockMvc и интеграционные тесты
репозиториев с H2.

Запуск всех тестов:

```bash
mvn test
```

#### Проверка API через Newman

Для проверки HTTP API используется Postman-коллекция спринта 15.

Newman можно запускать через `npx`, без глобальной установки:

```bash
npx newman run postman/sprint-15.postman_collection.json
```

Перед запуском коллекции должны работать PostgreSQL и приложение ShareIt на порту `8080`.

Для сохранения результатов в JSON:

```bash
npx newman run "postman/sprint-15.postman_collection.json" \
  --reporters cli,json \
  --reporter-json-export newman-results.json
```

Результат контрольного запуска коллекции:

- HTTP-запросов: 137
- Проверок (assertions): 128
- Ошибок: 0

### API

Основные группы эндпоинтов:

| Ресурс       | Базовый путь              |
|--------------|---------------------------|
| Пользователи | `/users`                  |
| Вещи         | `/items`                  |
| Бронирования | `/bookings`               |
| Отзывы       | `/items/{itemId}/comment` |

Для операций, требующих идентификации пользователя, используется HTTP-заголовок `X-Sharer-User-Id`.

### Структура проекта

Основные компоненты приложения организованы по функциональным областям: пользователи, вещи, бронирования и отзывы.

Для работы с данными используются JPA-сущности и репозитории, бизнес-логика реализована в сервисах, HTTP-запросы
обрабатываются контроллерами. DTO и мапперы отделяют API от модели хранения данных.
